# Glide Video Toolkit · Jellyfin 12.2

Glide 的独立 Jellyfin 插件，在服务器保存视频方向、处理批量队列和生成旋转后的预览。视频不经过手机中转。

- 独立仓库：https://github.com/sssnto/GlideToolkit
- 最新安装包：https://github.com/sssnto/GlideToolkit/releases/latest
- 插件存储库地址：**https://raw.githubusercontent.com/sssnto/GlideToolkit/main/manifest.json**
- 当前版本：**1.1.1.0**；面向 Jellyfin **12.2 / .NET 10 / Linux Docker**，ARM64 与 x64 共用托管 DLL。其他版本暂未提供匹配安装包。

## 在 Jellyfin 管理后台安装（推荐）

1. 使用管理员登录 Jellyfin，进入 **控制台 → 插件 → 存储库 → 添加**。
2. 名称填写 `Glide Toolkit`，存储库 URL 填写上面的完整 `manifest.json` 地址，保存。
3. 返回 **插件 → 目录**，找到 **Glide Video Toolkit**，选择 **1.1.1.0** 安装。
4. 等待安装完成，重启 Jellyfin 容器。在“我的插件”确认版本 **1.1.1.0** 并打开插件设置。
5. 按下面说明授权需要使用的用户及可写媒体目录。首次使用请用原创短片或视频副本验证。

NAS 需要能访问 `raw.githubusercontent.com`、`github.com` 及 GitHub Release 下载服务。目录未立即出现时，刷新插件目录并确认服务器版本符合要求。

### 从手动安装的 1.1.0 迁移

先等待当前旋转任务完成，然后添加此存储库，在目录里主动选择 **1.1.1.0** 安装并重启。插件 GUID 保持 `9e405477-411c-4c2b-8541-c3b5925f7169`，配置、任务记录和 `.glide-rotation` 备份继续沿用。旧手动包关闭了自动更新，**首次迁移需要主动在目录安装新版**；不要仅添加存储库后等待。Jellyfin 管理不同版本，不要再复制另一份 DLL，也不要删除配置、任务记录和媒体备份。

1.1.1 仅增加独立发布和存储库安装，旋转处理与 1.1.0 相同；未增加新的文件写入范围。新安装包允许 Jellyfin 按其插件更新设置检查后续版本，管理员仍可选择手动更新。


## 1.1.0 批量队列与旋转缩略图

配合 Glide 1.16.0（12）及更新客户端；构建 13 改为当前网格直接勾选，不需要再次升级插件。视频列表 → 更多 → **批量旋转**，选中需要修正的视频和方向，确认后加入服务器队列。**旋转任务**可查看已保存、剩余、失败、取消和待核对数量，支持暂停后续任务、继续、取消未开始的视频，以及仅重试失败项。

- 每批最多 1,000 个视频、每用户最多 8 个未完成队列。只向现有串行处理器派发一个批量子任务，不会同时备份或校验一批大视频。
- 队列保存在 Jellyfin 配置数据目录，离开 Glide 或服务器重启后可恢复。每条子任务的唯一请求 ID 先持久化，丢失响应时核对原任务，不重复旋转。
- 暂停／取消不打断当前文件的备份、替换与校验。保存结果不确定时暂停队列，保留备份，先核对再继续。
- 手机不下载、上传这些视频。处理时仍为当前文件预留两份文件大小加 128 MiB 的可用空间；备份长期保留，空间不足会暂停后续任务。
- 列表展示“方向已保存／已还原／等待旋转／正在旋转／未完成”等状态。旋转后按文件修订生成新的预览帧，最多一个封面解码任务，服务端缓存最多 1,000 张／256 MiB。电影及节目海报保留，家庭视频与单集预览使用新帧。
- 批量操作处理服务器可明确解析的主文件；多版本无法确定主文件时记录失败，请在播放器选择版本后单独保存。第一版仍限 MP4／MOV／M4V，无重编码。

升级：等待当前文件处理完成，停止 Jellyfin 容器，将 **1.1.0 安装包的 DLL 和 meta.json** 替换到当前插件目录，再启动并在“我的插件”确认 **1.1.0.0**。保留原目录、配置、`glide-rotation-jobs`、`glide-rotation-batches` 和媒体旁的备份。不要另建第二份插件。客户端仍可用 1.0.3 做单文件保存，但批量队列与旋转后新预览要求 1.1.0。

本地官方 Jellyfin 12.2 的文件、缩略图和重启恢复已通过。用户于 2026-11-11 确认 NAS 可完成旋转和保存，随后确认 1.16.0（13）的原网格勾选测试完成；该反馈没有逐项拆分结果，不外推为所有 NAS 的兼容验证。Glide 2.0 继续沿用 1.1.0 协议。

## 历史：1.0.3 修复及升级

媒体卷通过 SMB2 挂载时，原片读取句柄的共享锁可能是强制锁。1.0.3 在提交前关闭全部自持原片句柄，额外检查原文件可写及独占锁是否确实取得，随后释放锁并关闭句柄再进行发布。检查失败在备份或替换前停止。客户端构建 11 的最终修复包拒绝向 1.0.0–1.0.2 提交保存。

1.0.0 在部分 NAS 上发生替换失败、原路径缺失的问题，停止使用该版本保存方向。已有 `.bak` 和 `.part` 都保留，不要再次处理同一原片。1.0.3 优先使用已验证的原子交换；NAS 拒绝交换时，再独立检测同目录原生 POSIX rename。后者将临时输出放在原视频同一父目录，只调用原生 rename，不回退到跨目录复制或先删后写；两种方式均未通过则在修改视频前拒绝。1.0.1 已在用户 NAS 检出 `atomic_exchange_22`；1.0.2 的同目录方式仍因 SMB 文件句柄未关闭而失败。这两版都不用于本次 NAS 保存，请升级 1.0.3。

**升级已安装的插件：** 停止 Jellyfin 容器，解压 `GlideToolkit-1.1.0-Jellyfin-12.2.zip`，将 `Jellyfin.Plugin.GlideToolkit.dll` 和 `meta.json` 替换到**现有插件目录**，例如 `/config/plugins/GlideToolkit_1.0.0.0/`，再启动容器。目录名可以保留旧版本编号；实际版本由 DLL 和 meta.json 确定。不要另留一个可加载的旧版 DLL，也不要删除插件配置、任务记录和媒体备份。当前 1.1.0 安装包在管理后台应显示 **1.1.0.0**。

若之前的 UUID 测试短片原路径已经缺失，请在容器仍停止时，先从保留的原创短片复制回同一目录、同一文件名，再启动。启动时会只读核对旧任务；完整原始摘要吻合后结束异常状态。然后刷新对应媒体库。保留已有 `.bak` 和 `.part`，不覆盖私人原片。

Glide **1.16.0（11）** 最终修复包会拒绝使用 1.0.0–1.0.2 插件保存方向。升级之后先用原创片或原视频的副本验证；如果目录提示安全替换检查失败，保留原文件，向我们提供日志中的 `atomic_...` 错误编号。不要用跨目录移动、先删后写等方法绕过此检查。

### 原视频已消失时恢复

优先在 NAS 文件管理器中把对应任务的 `.bak` **复制**回原目录并恢复原文件名；同名文件已存在时取消覆盖。保留隐藏目录中的两个文件。之后刷新对应 Jellyfin 目录，确认能播放。

1.0.3 也提供管理员恢复入口：Jellyfin 管理后台 → 我的插件 → Glide Video Toolkit 设置 → **异常任务恢复**。查找异常任务，或输入日志中的完整任务 UUID，先“核对原片和备份”，再“从备份补回缺失原片”。它使用服务器任务记录确定路径和完整 SHA-256，不要求视频仍在片库中；只补回不存在的目标文件，保留 `.bak` 和 `.part`。普通用户不能调用；停用正常旋转保存时管理员仍可恢复。底层目录未通过安全文件操作检测时，改用上述文件管理器复制恢复，不会尝试覆盖。

已经通过文件管理器恢复的原片，若仍有异常任务，可以核对后点“确认原片已恢复”。服务器只在完整摘要匹配时结束该异常任务，不会再次改写视频。

恢复大文件会在 NAS 内复制并校验，需要等待。浏览器连接断开时先重新核对任务，原位置已完整恢复则不会重复写入。原位置已有其他内容时一律拒绝覆盖。

Jellyfin 服务器端的无重编码视频方向保存。Glide 播放器只提交媒体 ID、当前媒体版本、方向和请求编号；视频不会下载到手机或由手机上传。

第一版支持 Linux Docker 上的 Jellyfin **12.2**，MP4／MOV／M4V 单视频轨；ARM64 与 x64 使用同一托管 DLL。方向保存在容器的视频轨显示矩阵中，需要播放器支持该矩阵。不是逐帧转码，不扩展到 MKV／AVI 等格式。Emby 不安装此 Jellyfin 插件。

## 在 NAS 手动安装

1. 解压 `GlideToolkit-1.1.0-Jellyfin-12.2.zip`，得到 `Jellyfin.Plugin.GlideToolkit.dll`、`meta.json`、校验文件和安装说明。
2. 在 NAS 的 Docker 管理界面查看 Jellyfin 容器的卷映射，找到**容器内 `/config` 对应的 NAS 目录**。例如 `/volume1/docker/jellyfin/config`，这只是示例，不是你的实际路径。
3. 新安装时，在该配置目录的 `plugins` 下新建 `GlideToolkit_1.0.0.0` 文件夹，将 DLL 和 meta.json 放进去。沿用这个目录名是为了与旧版安装脚本一致，实际版本为 1.1.0.0。最终对应的容器内路径为：

   ```text
   /config/plugins/GlideToolkit_1.0.0.0/Jellyfin.Plugin.GlideToolkit.dll
   ```

   LinuxServer.io 或定制镜像若使用其他配置路径，以 Jellyfin 控制台显示的实际插件目录为准。不要复制整套 Jellyfin 依赖 DLL。
4. 启动 **Jellyfin 容器**。进入 Jellyfin 网页管理后台 → 插件 → 我的插件，确认出现 **Glide Video Toolkit 1.1.0.0**；日志也应显示已加载该插件。
5. 打开插件设置，默认启用。管理员账号可直接使用。若 Glide 登录的是普通账号，在“额外授权用户 ID”中填写对应 Jellyfin 用户 ID；每行一个。仍然受用户原来的媒体库可见性限制。
6. 可在“允许修改的容器内目录”进一步限制范围，例如 `/media/home-videos`。留空时限于现有 Jellyfin 媒体库中的服务器本地文件。这里使用 **Jellyfin 容器内路径**，不填 WebDAV 地址或 NAS 宿主机路径。
7. 确认媒体卷可写、Jellyfin 运行用户有文件和父目录写入权限，并为备份及临时文件预留至少约两倍原文件的可用空间。已有备份另占空间；系统会在处理前检查空间。

首次用可覆盖的测试视频：在 Glide 1.16.0（11）或更新验证包播放 Jellyfin 视频 → 播放设置 → 视频方向与保存 → 左／右转预览 → **保存到服务器原文件**。确认框显示当前文件名。保存后原位置重新播放；“从备份还原”会检查当前文件未被其他修改，并在还原前保留当前版本。

客户端断开后服务器任务继续。重新打开同一媒体版本的方向面板可查看任务或核对未确认结果。服务器在替换前重启，任务会安全标记为中断，原文件不替换；如果重启发生在替换附近，会只读核对原文件、输出和备份，避免重复旋转。

### 可选：NAS 终端安装

本脚本适用于上述标准 `/config/plugins/GlideToolkit_1.0.0.0` 目录，其他安装目录请手动替换。先停止容器，将压缩包解压到 NAS 的一个目录后，在该目录执行：

```sh
docker stop 你的Jellyfin容器名
sh install-docker.sh 你的Jellyfin容器名
```

脚本校验 DLL 和 meta.json 并复制到容器的标准插件目录；要求容器已停止，默认**不启动**。确认安装输出后自行执行：

```sh
docker start 你的Jellyfin容器名
```

镜像配置目录不是 `/config` 时请按前述卷映射方法手动安装。脚本不修改媒体卷、不导出容器环境变量或账号密码。

## 备份和恢复记录

- 每个原文件所在目录的 `.glide-rotation` 内保留 UUID 命名的 `.bak` 备份；目录仅 Jellyfin 服务用户可访问。不要把这个目录当作普通媒体导入，也不要在需要还原时删除它。
- 事务记录位于 Jellyfin 数据目录的 `glide-rotation-jobs`，通常为 `/config/data/glide-rotation-jobs`。保存 Docker 的配置卷时一并保留。
- 备份保留完整原始字节。替换前验证矩阵外的所有字节不变，检查文件版本和完整摘要；保留 NAS 原文件的所有者、权限及可读取的扩展属性，不能保留则在替换前拒绝处理。
- 同文件同时只接受一项任务；正在其他设备播放时先等待，超时后拒绝替换。API 不接受客户端文件路径和外部 URL；默认不授权普通用户写入。
- 第三方程序仍应避免同时编辑同一原文件。文件系统锁对不遵守锁的外部工具不是全局事务锁；本实现使用替换前版本／完整摘要复核和经过同目录探测的原生 rename 或 `renameat2(RENAME_EXCHANGE)`，不能承诺对任意外部写入程序提供文件系统级 CAS。交换模式保存成功后 `.part` 是交换出的前一版本；同目录 rename 模式使用原视频父目录的 UUID 隐藏 `.part`，提交成功后它被消耗，完整原始备份仍在 `.glide-rotation/*.bak`。失败任务的 `.part` 含义以任务记录和摘要核对为准，不要当作原片盲目覆盖。
- 默认不自动删除历史备份。空间不足时任务拒绝，先处理备份空间再重试；不要删除尚未确认结果的任务记录。

## 独立构建与验证

需要 .NET 10 SDK，依赖固定为 Jellyfin.Controller／Model 12.2.0。仓库不包含 Jellyfin 运行时依赖。

```sh
git clone https://github.com/sssnto/GlideToolkit.git
cd GlideToolkit
mkdir -p artifacts
dotnet build Jellyfin.Plugin.GlideToolkit/Jellyfin.Plugin.GlideToolkit.csproj -c Release
dotnet run --project GlideToolkit.Tests/GlideToolkit.Tests.csproj -c Release -- test-media/original.mp4 artifacts/core-report.json
python3 scripts/package.py
python3 scripts/verify_repository.py --local
```

本地打包生成安装 ZIP、SHA-256 清单及待发布的 `manifest.json`；主分支存储库清单只在安装包成功发布后更新。

发布新版本：先修改项目的 `Version`，合并代码并确认 CI 通过，再推送对应的 `vX.Y.Z` 标签。Release workflow 会重新构建、运行原创片回归、打包、创建 GitHub Release，最后更新主分支 `manifest.json`。版本标签必须与程序集版本一致，已发布版本不覆盖。清单保留旧版本，Jellyfin 使用固定的插件 GUID 和目标 ABI 匹配版本。

需要端到端回归的原有隔离容器脚本仍在 [Glide 客户端仓库的 Scripts](https://github.com/sssnto/Glide/tree/main/Scripts)；只针对本机原创素材，不操作用户 NAS。插件依赖的 Jellyfin 项目采用 GPL-3.0，服务端代码和依赖不引入 iOS 二进制。

安装失败可先把本次插件版本目录移到插件搜索目录之外，再重启 Jellyfin；保留媒体旁的备份和数据卷中的事务记录。不要删除任务记录或用历史 `.part` 盲目覆盖原视频。
